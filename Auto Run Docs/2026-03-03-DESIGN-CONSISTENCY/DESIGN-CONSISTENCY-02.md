# P0: Dark Mode Gaps — EmojiPicker, HabitCard Colors, CalendarTimeline

These components use static `colors.light.*` imports instead of `useThemeColors()`, locking them to light mode.

## Context

- Theme system: `useThemeColors()` from `@/theme/ThemeContext` returns `{ colors, isDark }` where `colors` implements `SemanticColors` (has `.background`, `.card`, `.surface`, `.border`, `.text.*`, `.gray.*`, `.primary.*`)
- `colors.light.*` is a static object in `@/theme/colors/core.ts` — ONLY light mode values
- `lightColors` and `darkColors` from `@/theme/darkColors` are the full semantic palettes
- Files should either: (a) accept colors via props from a parent that calls `useThemeColors()`, or (b) if they're React components, call `useThemeColors()` directly
- Style files (`.styles.ts`) can't call hooks, so they should either export style-creator functions that accept colors, or use static `colors.*` tokens that don't change with theme (like `colors.primary[600]`, `colors.gray[500]`)
