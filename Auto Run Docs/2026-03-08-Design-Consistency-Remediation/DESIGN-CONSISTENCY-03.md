# Phase 03: Spring Config & Inline Style Token Adoption

**Goal:** Replace all inline spring configs with theme spring tokens, and replace hardcoded border radius / shadow values with theme tokens in component style files.

**Context:** 5 components use inline `{ damping: X, stiffness: Y }` instead of `springs.*` tokens. Additionally, 100+ instances of `borderRadius: 12` and 50+ of `borderRadius: 16` bypass the `borderRadius.*` tokens. Shadow opacity values (0.08-0.3) vary instead of using `shadows.*` presets.

---

- [ ] **Replace inline spring configs with theme tokens**: (1) `src/components/StrengthRing/useStrengthRingAnimation.ts` — replace `{ damping: 15, stiffness: 200 }` with `springs.responsive` (damping 15, stiffness 300 — closest match; if the stiffness difference matters, create `springs.progressFill` with `{ damping: 15, stiffness: 200 }` in `src/theme/animations.ts` instead). (2) `src/components/DraggableHabit/useStrengthAnimation.ts` and `src/components/DraggableHabit/useCardStrengthFill.ts` — both use `{ damping: 12, stiffness: 100 }`, which matches no existing token. Add `springs.fillProgress: { damping: 12, stiffness: 100 }` to `src/theme/animations.ts` and reference it in both files. (3) `src/components/HabitCard/entrance/animations/widthExpansion.ts` — uses `{ damping: 12, stiffness: 200 }` which is exactly `springs.celebration`. Replace with `springs.celebration`. This file already imports from `@/theme/animations`.

- [ ] **Replace MilestoneCelebration spring constants with theme tokens**: File: `src/components/MilestoneCelebration/constants.ts`. The `ANIMATION_TIMING` object defines `BADGE_BOUNCE_DAMPING: 10, BADGE_BOUNCE_STIFFNESS: 180` (= `springs.bouncy`) and `BADGE_SETTLE_DAMPING: 18, BADGE_SETTLE_STIFFNESS: 150` (= `springs.standard`). Replace these with imports from `@/theme/animations`. Update `src/components/MilestoneCelebration/animationSequences.ts` to use `springs.bouncy` and `springs.standard` directly instead of destructuring from the constants object. Keep other non-spring constants (GLOW_DURATION, delays) in the constants file but consider replacing duration values with theme tokens too (GLOW_DURATION: 400 = `durations.emphasis`, LABEL_DURATION: 300 = `durations.moderate`, PERCENTAGE_DURATION: 500 = `durations.complex`).

- [ ] **Replace hardcoded `borderRadius: 12` with `borderRadius.medium` or `borderRadius.button`**: Search the `src/` directory for `borderRadius: 12` (not in theme files). For each occurrence, replace with `borderRadius.medium` (or `borderRadius.button` — they're the same value). Each file must import `{ borderRadius }` from `@/theme` or `@/theme/spacing`. This is a high-volume change (~100 instances) — use batch approach. Skip files in `src/theme/` (those define the tokens). Skip test files. If a file already imports from `@/theme`, add `borderRadius` to the existing import.

- [ ] **Replace hardcoded `borderRadius: 16` with `borderRadius.card` or `borderRadius.large`**: Search `src/` for `borderRadius: 16` (not in theme files). Replace with `borderRadius.card` (or `borderRadius.large` — same value). Same import pattern as above. This is ~50 instances.

- [ ] **Replace hardcoded shadow opacity values with theme shadow presets**: Search for `shadowOpacity:` in `src/components/`. For each, determine which `shadows.*` preset is appropriate based on the component's elevation level: chips/badges -> `shadows.subtle`, cards -> `shadows.card`, FABs/pressed -> `shadows.floatingActionButton`, modals -> `shadows.modal`. Replace the individual shadow properties (`shadowColor`, `shadowOffset`, `shadowOpacity`, `shadowRadius`) with a spread of the appropriate preset: `...shadows.card`. Key files: `src/components/SettingsModal/SettingsSection.tsx` (0.08 -> `shadows.subtle` or `shadows.card`), `src/components/ErrorBoundary/RetryableErrorView.tsx` (0.15 -> `shadows.card`), `src/components/ErrorBoundary/ScreenErrorFallback.tsx` (0.2 -> `shadows.floatingActionButton`), `src/components/ProgressSectionConsolidated/HeroStrengthSection/StrengthRing.tsx` (0.3 -> `shadows.modal`).
