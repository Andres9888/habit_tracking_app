Two ways to bring categories forward

Side-by-side comparison of the two patterns we discussed: the Nov 2025 chip rail revival, and a Netflix-style row-per-category layout. Same design tokens in both.

↗ Open Pattern A full-screen ↗ Open Pattern B full-screen

Pattern A — Chip Rail

Revival of the Nov 2025 layout · one horizontal rail of all 14 categories with counts, one vertical filtered list.

Pros

  • All categories visible — no hidden taxonomy
  • Counts communicate library breadth
  • Familiar filter pattern; low cognitive load
  • Cheapest to implement (expand existing QuickFilterChips)

Cons

  • Habits only appear AFTER a tap — less shoppable
  • Discovery depth still = 1 category at a time
  • Chip rail with 14 items is wide & eye-taxing
  • Spotlight + single list feels like the current screen minus personalization

Pattern B — Netflix Rows

5–6 horizontal rows, one per priority category · curated top list + "Browse all 14" CTA.

Pros

  • Actual habits visible from 6 categories at once — "shoppable" feel
  • Matches App Store / Netflix / Spotify mental model
  • Reuses the existing PopularSection carousel pattern
  • "See all →" per row + "Browse all" footer keeps full taxonomy reachable

Cons

  • Long screen (~2800px when all rows render)
  • Only 2–3 cards visible per row on mobile — looks sparse
  • 8 of 14 categories get buried behind "Browse all"
  • Replaces ExploreAllSection (recent polish work in #1319)

How to choose

Pattern A if the goal is "give power users faster access to filter the whole library." Pattern B if the goal is "turn the library into a browsable storefront where users discover habits by eye." The two solve different problems — A optimizes for filtering; B optimizes for discovery. They can also be combined: keep Pattern B's rows as the discovery surface, and expand QuickFilterChips to the full 14-category chip rail above them.
