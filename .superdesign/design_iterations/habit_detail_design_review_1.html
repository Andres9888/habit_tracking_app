What changes and why:

Habit Name Typography

Before: fontSize: 34, letterSpacing: -0.5, font-bold (system font)

After: ...typography.displayLarge → Literata serif, letterSpacing: -0.85

Why: The design system specifies Literata (serif) for display headings to create emotional weight. The current code uses the system sans-serif font, breaking the serif/sans-serif pairing that distinguishes display text from body text across the app. The letterSpacing -0.85 is tighter than -0.5 for better large-text optical balance.

Schedule Text

Before: className='text-[13px]' (Tailwind arbitrary, no fontFamily/letterSpacing/lineHeight)

After: style={{ ...typography.caption, color: colors.text.secondary }}

Why: The caption token includes fontFamily (DM Sans), letterSpacing (0.12), lineHeight (18px), and fontWeight (500). Using the arbitrary class only sets fontSize, missing all other properties. If the type scale ever changes, this text won't update.

Checkmark Color

Before: color='#FFFFFF'

After: color={colors.text.inverse}

Why: Hardcoded white won't adapt to theme changes. colors.text.inverse is the semantic token for text on colored backgrounds. In light mode it resolves to #FFFFFF, in dark mode to #111827.

Edit Icon Size

Before: size={15} (off-grid)

After: size={16} (standard icon grid)

Why: The icon size system uses even numbers (10, 12, 14, 16, 18, 20, 24...). 15px is off-grid and renders with sub-pixel antialiasing, causing slight blur on non-retina displays.

2. QuickStatsRow

MEDIUM

src/screens/HabitDetailScreen/components/QuickStatsRow.tsx

The stat pills use raw pixel numbers for gap and padding instead of spacing tokens. The values happen to match tokens, but they bypass the system.

Current
gap: 4,
paddingHorizontal: 12,
paddingVertical: 6,
gap: 8,
paddingVertical: 8,
After
gap: spacing.xs, // 4
paddingHorizontal: spacing.md, // 12
paddingVertical: 6, // keep (between xs:4 and sm:8)
gap: spacing.sm, // 8
paddingVertical: spacing.sm, // 8
Why replace matching values with tokens?

If spacing.sm changes from 8 to 10 during a design refresh, raw 8 stays frozen while spacing.sm updates everywhere. Tokens make the design system the single source of truth. Also: developers reading spacing.sm immediately know "this follows the grid" vs. a magic 8 that could be anything.

3. DetailViewTabs

MEDIUM

src/screens/HabitDetailScreen/components/DetailViewTabs.tsx

The animated pill indicator defines its own shadow inline instead of building on the shadows.card token.

Current (inline shadow)
elevation: 3,
shadowColor: accentColor,
shadowOffset: { height: 3, width: 0 },
shadowOpacity: 0.12,
shadowRadius: 8,
After (token + override)
...shadows.card,
shadowColor: accentColor,
// shadows.card gives: elevation 3,
// offset {h:2}, opacity 0.06, radius 8
// only shadowColor is custom (accent tint)
Why use shadows.card as base?

The shadow token system defines 5 elevation levels with warm-toned #2D2A26 shadow color for tonal consistency. The inline shadow uses accentColor for a tinted glow, which is intentional and good — but the base metrics (elevation, radius) should come from the token so elevation hierarchy stays consistent if the shadow system is updated.

4. DetailViewTabButton

MEDIUM

src/screens/HabitDetailScreen/components/DetailViewTabButton.tsx

Tab label uses Tailwind arbitrary text-[13px] and inline fontWeight instead of typography tokens.

Current
className='text-[13px]'
fontWeight: isActive ? '600' : '500'
After
style={{
  ...typography.caption,
  fontWeight: isActive
    ? fontWeights.semibold
    : fontWeights.medium,
  color: foreground,
}}
Why?

typography.caption includes fontFamily (DM Sans), letterSpacing (0.12px), and lineHeight (18px) — all missing from the arbitrary Tailwind class. The fontWeights tokens make it explicit that '600' = semibold and '500' = medium, improving readability.

5. HeaderButton

HIGH

src/screens/HabitDetailScreen/components/HeaderButton.tsx

The "Edit Habit" button uses 6 raw numbers that have exact token equivalents.

Current (raw numbers)
borderRadius: 24
gap: 8
height: 44
paddingHorizontal: 16
opacity: 0.7
fontSize: 14, letterSpacing: -0.2
After (tokens)
borderRadius: borderRadius.xl // 24
gap: spacing.sm // 8
height: componentSpacing.button.height // 44
paddingHorizontal: spacing.base // 16
opacity: OPACITY.high // 0.7
...typography.bodySmall, letterSpacing: -0.2
Why?

Every one of these raw values has an exact token match. Using tokens communicates intent: componentSpacing.button.height says "this is a button" while 44 says nothing. If the design system standardizes buttons to 48px, all tokenized buttons update together.

6. DetailHeader.constants

LOW

src/screens/HabitDetailScreen/components/DetailHeader.constants.ts

The icon shadow is missing shadowColor, causing it to default to black instead of the warm #2D2A26 used by all other shadows in the app.

Current (missing shadowColor)
iconShadow = {
  elevation: 6,
  shadowOffset: { height: 6, width: 0 },
  shadowOpacity: 0.15,
  shadowRadius: 16,
  // no shadowColor → defaults to #000
}
After (warm shadow)
iconShadow = {
  elevation: 6,
  shadowColor: '#2D2A26',
  shadowOffset: { height: 6, width: 0 },
  shadowOpacity: 0.15,
  shadowRadius: 16,
}
Why?

All 5 shadow tokens in spacing.ts use shadowColor: '#2D2A26' (warm stone-brown) for tonal consistency with the warm neutral palette. Missing it here causes the hero icon to cast a cooler black shadow compared to every other elevated element.

7. SectionLabel

LOW

src/screens/HabitDetailScreen/components/SectionLabel.tsx

Section divider text uses Tailwind arbitrary styling instead of typography token.

Current
className='text-[13px] font-semibold tracking-wider'
// No fontFamily, no lineHeight
After
style={{
  ...typography.caption,
  fontWeight: fontWeights.semibold,
  letterSpacing: 0.8,
  color: textColor,
}}
Why?

Same principle as tab labels: typography.caption provides the complete text style (fontFamily, fontSize, lineHeight, letterSpacing, fontWeight). The wider letter-spacing is overridden since section labels use wider tracking as a design choice for divider text.

Summary of Changes

All fixes are token substitutions. The rendered pixel values are identical (or nearly so for letterSpacing on the habit name). No layout shifts, no color changes, no animation changes.
