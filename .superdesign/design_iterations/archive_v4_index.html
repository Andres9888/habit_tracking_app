Archive Habits — 10 Tweak Variations

Each mockup is a small, comparable tweak to the existing card-list, not a full redesign. Every variation starts from the same baseline (same palette, typography, card anatomy, corrected copy, Back-only header) so differences are about the problem solved, not the skin.

North-star question: If a user opens this screen, what's the shortest path to their goal?
Speed-to-restore Bulk management Context before action Interaction model Safety / limits
v4.1
Asymmetric CTAs
Problem: Resume is far more common than Delete, but both buttons have equal weight. Tweak: Resume becomes a full-width green pill; Delete shrinks to a quiet corner icon.

v4.2
Recently Archived Section
Problem: Most restore requests target habits archived in the last 24–48h (accidents). Tweak: Pin last-7-days archives in a top section with an "Undo archive" chip; older archives collapse out of the way.

Which tweak solves which user task?

Restore a fresh accidental archivev4.1 (big Resume) + v4.2 (pinned recent)

Know if restore is blocked by free-tier limitv4.4 (proactive lock)

These tweaks are mostly additive — a shipped version will combine 3–5 of them. My recommended combo for a single follow-up PR: v4.1 + v4.4 + v4.5 + v4.10 — big Resume for the common path, proactive lock so no-one wastes a tap, header Select to unlock batch (reuses existing code), danger footer to unlock Delete All (reuses existing code). That's four high-impact wins with low additive scope.
