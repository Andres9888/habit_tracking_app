Onboarding — hybrid benefit pivot

Each new screen does three things at once:
  • Benefit-driven headline — "You will…" — proven onboarding framework (Calm, Duolingo, Headspace).
  • Concrete mechanic — the visual shows the actual feature, so the promise feels real, not vague.
  • Implicit pain answered — replaces the cut questionnaire by addressing the same 4 pains structurally.

Pain → benefit map:
  • "I quit when I miss a day." → You won't end up at zero.
  • "I can't tell if it's sticking." → You'll watch it transform.
  • "I try too many at once." → You'll finish what you started.
  • "Novelty wears off." → Always one peak to chase.

How this respects the benefit-driven framework
  • Headlines are "you will…" outcome statements — same shape as Calm/Duolingo/Headspace.
  • Each screen ends with Continue CTA — proven low-friction step pattern.
  • Progress chrome appears — users can see how far they've come.
  • Sequence builds specificity: zero → transform → focus → forever — emotional → visible → constraint → sustained motivation.

Where it diverges (deliberately)
  • The mechanic visual proves the benefit. Calm shows mood; we can show the actual route mechanic. Stronger trust signal.
  • One metaphor (route) carries all four screens. Lower cognitive load than four separate visual languages.
  • Ends with a real action (start the route) instead of bridging into a long questionnaire. The hook lasts longer in the user's head if they leave it already moving.

Open questions
  • Should screen 8 be after a brief social proof / Seinfeld beat, or replace it?
  • Does Name capture happen before screen 8 (so we can say "Start your first route, Andres") or after (post-action, less friction)?
