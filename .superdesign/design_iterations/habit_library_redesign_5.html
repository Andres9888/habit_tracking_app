What's wrong with current v3

Problem 1: Long, flat scroll. 6 categories × 3 habit rows + headers ≈ 30+ scroll screens before the bottom is reached.

Problem 2: Top-3 preview is noise. A user scanning for the right category reads 18 habit names they don't care about before finding the one they do.

Problem 3: Every row looks equally loud. No hierarchy between "here's the taxonomy" and "here are the habits in one area."

What v5 implementation delivers

Scan first, commit second. All 6 categories visible as slim cards on one screen. User picks the area, then reads habits.

Card + chevron = proper list control. AccordionCategoryCard with warm-white open bg + CategoryChevron (20×20, rotates 180°, tints primary[100]).

Section copy matches intent. "Discover more habits" / "Tap a category to explore" + monospace habit count.

Multiple can stay open — per-card useState, no radio behavior, so user can compare across categories.
