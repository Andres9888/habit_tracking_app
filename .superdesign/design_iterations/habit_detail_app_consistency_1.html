Habit Detail — does it match the rest of the app?

Architecturally yes, chromatically no. Each row shows the current build first, then the alternatives, with a real home habit card (#EDEAE5) and Habit Browser card (#F8F5F1) in frame so you judge against the actual neighbours, not in isolation. Rows 1–2 are taste calls. Row 3 is not — every "after" there is an existing token, an existing primitive, or a documented rule. Dark toggle bottom-right.

Provenance: 42 of the 57 hex values here are copied from source (src/theme/, HabitCard.colors.ts, the three screen palettes, the spec doc). Of the rest, 10 are this page's own chrome — body background, prose grey, BEFORE/AFTER labels — and 4 are invented: the dark-mode wash stops #16302A/#14211E (green) and #1B2230/#161C27 (neutral). They have to be, because the current code builds its dark stops with withAlpha(green, 0.2) rather than opaque hex — which is itself finding 3g below. Treat the dark washes as indicative only; the light column is exact.

1 Hero wash

The wash is the one thing that visually separates this screen from the rest of the app. docs/human-optimized-frontend-spec.md:48 says background gradients should be neutral parchment → #EDE8E0. Every other structural wash in the app is neutral (Welcome) or warm (template drill-down) — green is new. The counter-argument is real though: FullsizeTemplatePreview already establishes "one fixed tinted wash per drill-down surface", so only the hue family is unprecedented.

2 Card fill

Three fills are live in the app right now: home #EDEAE5, Habit Browser and template #F8F5F1, habit detail #FFFFFF. White is not drift — core.ts:101 defines cardElevated with the comment "Pure white card — Habit Detail hero/section cards", and spec:37 lists surface cream as #FFFFFF. But b8f32131f moved template cards off white for a stated reason and repurposed cardElevated in the same commit. Watch the two context cards at the bottom of each frame — that's the list→detail transition.
