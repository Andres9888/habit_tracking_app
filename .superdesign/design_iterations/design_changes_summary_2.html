1 · Pre-existing bugs the cleanup fixed

These are the ones to spot-check. Each was rendering wrong before — components were defaulting to regular weight or showing fallback colors because of typos and shadowing bugs. Now they render the way the original code clearly intended.

★ Bug fixed typography.bodyBold — 7 components now actually render bold
HabitRankingsList · WeeklyInsightsCard · TrendLineChart · ExportMenu · StrengthDistributionChart Legend · ItemStyles habitName + rankNumber
Root cause: the typography object never defined a bodyBold token. Components used ...typography.bodyBold spread which was undefined — spreading undefined is a silent no-op, so these elements rendered with the default regular weight instead of bold.
Where to look: habit names + rank numbers in the Habit Rankings view (Analytics or wherever rankings appear); change-percentage text in the WeeklyInsightsCard; legend labels in trend/strength charts; the export-menu button label.

★ Bug fixed DayBar — chart bars in 60–79% range no longer broken
src/components/InsightsSection/components/DayBar.tsx
Root cause: the function called colors.secondary[400] on the semantic colors object — but semantic colors don't have a top-level secondary namespace (only text.secondary as a flat string). At runtime this resolved to undefined, so the bar's background color was undefined.
Where to look: the bar-chart in Analytics → Insights → "Best Days" / week-day rates. Any day where completion rate is between 60% and 79% (and isn't best/worst). Was rendering with no color or weird inherited tone — now renders the intended blue (secondary[400]).

★ Bug fixed FeedbackModal — section + type labels now semibold (were regular)
src/components/FeedbackModal/FeedbackModal.styles.ts:70,116
Root cause: property order. fontWeight: semibold was declared but then immediately overwritten by ...typography.body spread which carries fontWeight: regular. Reordered so the spread runs first then explicit weight wins.
Where to look: open Settings → Send Feedback. The labels above the radio choices and the radio item titles were rendering at regular weight; now semibold.

4 · Decision points — what's still open

Each of these needs a per-case design call. The mock can't auto-decide for you.

Wave 1.2 — Shadow migration (427 inline sites → ~83 token sites)
Per-file judgment matching inline shadow patterns to shadows.subtle / card / floatingActionButton / modal / alert. Starting with top 5 highest-traffic files would be safest.
Wave 2.2 — Custom text-[Npx] Tailwind classes (155 sites)
Same mapping problem at the NativeWind layer (15px doesn't snap cleanly to text-sm/text-base).
Wave 2.4 remainder — 53 non-canonical borderRadius values
Values 2/5/10/14/18/20/32 — none map exactly. Snap-to-nearest produces visible changes per site.
Wave 2.5 — 757 raw hex values
Long-tail. Many are intentional (gradient endpoints, achievement palette, material tier ramps). Each migration needs intent verification.
Wave 3.1 — Unified Button primitive (architectural)
Proposed in design_system_showcase_1.html Section 7 — 3 sizes × 4 variants. Replaces 290 inline Pressable/TouchableOpacity instantiations. Needs API sign-off.
Wave 3.2 — EmptyState consolidation
17 distinct EmptyState.tsx files. Likely 10 can collapse onto the canonical primitive; 7 chart-specific stay custom.
Wave 3.3 — Animated.Value → Reanimated (31 files)
Motion QA per component. Overlaps with 14 remaining legacy Animated.spring friction/tension sites.
Wave 3.4 — NativeWind vs StyleSheet (architectural)
300+ files mix both. Pick one or formalize boundary rules. Conversation, not sed.
