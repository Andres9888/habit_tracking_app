Why this is better

Phase 1.1 + 1.2 — wiring up dormant components. Two surgical additions, real user-pain motivations, hypothesized monetization impact.

PHASE 1.1 QuickFilterChips

Problem today: ~328 templates, 17 categories. Narrowing to "sleep templates" requires scrolling past goal grid → past popular → finding the Sleep row → tapping "See all". 3+ taps for a common task. Most users give up.

"I can't tell which habits to focus on, so I try too many at once." — onboarding-v2 pain point #3

Why it helps:
  • Hick's Law: 7 visible chips beat scrolling 17 buried categories. Faster decisions.
  • Recognition over recall — labels visible vs "what categories exist?"
  • Always above the fold — chips persist whether browsing or filtering.

PHASE 1.2 StartHereCard

Problem today: A new user (0 habits) opens the library and sees the same overwhelming surface as a power user. We literally captured "I try too many at once" in onboarding — and then show them 328 options. Why it helps:
  • Prescribed path — kills the blank-page problem for new users.
  • Easy wins — 5 short-duration habits → high completion → first streak hits day 3 → dopamine.
  • Auto-hides at 2+ habits — engaged users aren't talked down to.

HYPOTHESIS Monetization impact

Theory of change — not measured. Phase 1 is the prerequisite for Phase 2 (personalization) where the real lift comes.
1D1 activation: clearer path + faster filter → more users add a first habit before bouncing. Each habit = a reason to come back tomorrow.
2D3–D7 streak survival: StartHereCard biases new users toward 5-min habits with high stick rate. More streaks survive the friction valley.
3Trial → Paid conversion: paywall converts best on engaged users. Pushing more users into "3+ habits, 7-day streak" lifts conversion at the existing paywall.
4Churn reduction: users who never find a relevant template churn earliest. Chips compress time-to-relevant from minutes to seconds.

TRADEOFFS Honest counter-arguments

  • Chips show only 7 of 17 categories — productivity / longevity / breathing not surfaced. Mitigated: search + Explore-all rows still cover them.
  • StartHereCard's 5 habits are not personalized to the user's onboarding goal — a "Sleep" picker still sees "Drink Water". Phase 2 fixes this.
  • Phase 1 is dormant-code wiring. The bigger monetization lever is Phase 2 where the page actually differs between users with different goals/pains.

VALIDATE What to measure

Add events: library_opened, chip_tapped (per chip), start_here_tapped, template_imported with source = chip / goal-grid / popular / explore-all / start-here.

Single cleanest metric: % of new users who import a template within 60s of opening the library, before vs after.
