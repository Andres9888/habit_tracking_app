Cut from 7 → 5 by tweaking screen 3 to absorb anti-plateau, dropping screen 4 (now redundant), folding screen 5's visual into screen 6.

  1. welcome — "Hey" hook. unchanged
  2. problem — "You're building habits blind." tweak: drop "You're lost", update closing line
  3. solutionIntro — "Here's your map." tweak: step 3 → "Know what's next" (anti-plateau)
  4. onePeak + transformation — Combined: per-habit calibration shown with chain visual transforming. merge 5+6
  5. pickFirstRoute — Commit moment. fix: wire habit creation

Why this maximizes conversion: 5 screens vs 7 = 28% less friction. Each remaining screen is unique (no redundancy). Habit gets actually created on commit. Nothing valuable is lost — strength concept stays integrated into screen 3 step 3, deeper strength explainer can move into the app's first-check-in moment.

Detailed conversion analysis

Industry benchmarks

  • Top subscription apps (Headspace, Calm, Duolingo, Noom) average 5–9 onboarding screens.
  • Each additional screen typically costs 5–10% conversion at this stage. Going from 7 → 5 should lift conversion by ~10–20%.
  • Industry rule: every screen must EITHER teach a unique concept OR collect a unique data point. Redundancy kills conversion.

Where our 7-screen flow has friction

  • Screen 4 ↔ Screen 3 step 3 — both deliver "your strength holds, never back to zero." Two screens for one idea.
  • Screen 5 — pure visual reward. Beautiful but not load-bearing — could fold into 4 or 6.
  • Screen 7's commit doesn't actually persist — biggest single drop-off potential since user lands in empty state.

Where the flow already converts well

  • Screen 1's "Hey" — minimum-viable hook. Industry-standard low-friction entry.
  • Screen 2 → 3 narrative payoff — "blind / no map" → "here's your map" is structurally satisfying.
  • Screen 7's library escape hatch — gives commitment-anxious users an out without breaking flow.

What's notably MISSING vs proven flows

  • No notification permission ask — biggest retention factor in the wild. Push enabled vs not = 40-60% retention swing. Should add post-commit.
  • No social proof anywhere — no testimonials, user counts, or stats. Could add one screen between solutionIntro and onePeak ("12,000 chains forged") OR a single testimonial card on screen 7.
  • No first check-in moment — user emotionally commits but doesn't *do* anything. A first-action moment + notification ask + paywall, all post-commit, would match top-tier flows. (Currently lives outside onboarding-v2 in the AuthGate flow.)

If conversion is the only goal: 5 screens. If retention matters too: 6–7 with the missing pieces added back

  • 5-screen flow is fastest to commit but loses retention drivers (no notif, no first-check-in).
  • For BEST overall (conv + retention): 5 onboarding screens + 3 post-commit (firstCheckIn → notificationPriming → celebration) = 8 total but with full activation.
