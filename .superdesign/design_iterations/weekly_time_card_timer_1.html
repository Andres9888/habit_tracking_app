Decisions to confirm

Placement

Header text action ▶ Start when idle (low visual weight). Full timer band at top when running (high visibility, hard to forget). Confirmation band briefly replaces the timer band on stop.

Pause vs no-pause

Shown with ⏸ Pause in the header for completeness, but pause adds persistence + UX edges (auto-resume on app return?). Recommend shipping Start/Stop only; add Pause later if needed.

Optimistic live updates

While running, the totals row, week-bar, avg/day, on-pace pill, and today's cell all reflect persistedToday + (now − startedAt). Recompute every 10s (cheap; whole tree already redraws on minute changes).

Persistence

Store {habitId, startedAt} in AsyncStorage on Start; clear on Stop/cancel. On app launch, if a record exists for the current habit, restore the band. Cross-day boundary: split into yesterday + today on stop.

Open questions

  • Pause: ship in v1, or hold? Recommend hold.
  • Multiple habits running: allow concurrent timers, or single-active? Recommend single-active.
  • Background behavior: keep ticking when app is backgrounded — yes (we just compute from startedAt; no native timer needed).
  • Min-recordable: ignore stops under 30s? Or always log?
  • Where Start lives outside this card: floating action on Habits home, or only inside detail screen? Recommend detail-only for v1.
