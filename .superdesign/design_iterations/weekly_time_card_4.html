Where to put the trigger?

  • 1. Inline only — small ⚑ pill in the card header (current mockup). Tap opens the sheet. Pro: goal lives next to the data it shapes. Con: goal-setting is mixed with goal-viewing.
  • 2. Goal tab only — add a "Time goals" subsection inside the existing Goal tab, alongside the streak goal. Pro: all goals in one place. Con: two scrolls away from where you'd see the time data.
  • 3. Both — pill on the card opens the sheet directly; Goal tab also lists the time targets and lets you edit them there too. Pro: visible from both surfaces. Con: two code paths writing to the same fields.

Logic rules

  • Both unset → today's behavior. Total + cells, no progress bars.
  • Weekly only → top progress bar against weekly total.
  • Daily only → per-cell mini bar; cells turn solid when ≥ daily; "X of 7 hit" caption.
  • Both → weekly bar on top, per-cell mini bar, both captions. Cell completion uses daily; week bar uses weekly.
  • Daily can exceed → if cell hits 60m on a 30m goal, bar caps at 100% and cell stays "complete." Overage shown in the value (e.g., "60m").
Schema: add dailyMinutesGoal: v.optional(v.number()) and weeklyMinutesGoal: v.optional(v.number()) to habits. New mutation habits.setTimeGoals({ habitId, daily?, weekly? }). Sheet UI mirrors the existing Log-time sheet pattern (drag handle, chips, save, clear).
