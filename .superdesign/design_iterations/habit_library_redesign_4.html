Why an accordion (not just section-level collapse)

Two ways to collapse the long list:

Option A — whole section collapsed: "Discover more habits" shows a single header, tap to expand everything. Problem: once expanded, you're back to the same 30-screen scroll.

Option B — per-category accordion (chosen): 14 slim rows always visible, each shows label + count + chevron. Tap one to expand just that category's habits. User sees the full taxonomy at a glance, expands only what they care about. This is the v4 design.

Implementation scope

The existing CategoryGroupSection in ExploreAllSection.tsx already uses a per-group useState(expanded). Today expanded only toggles between "3 habits" and "all N habits."

v4 changes:

1. Flip default: const [expanded, setExpanded] = useState(false)
2. When collapsed: render only CategoryGroupHeader (no habit rows at all)
3. Make the header Pressable to toggle
4. Add chevron affordance inside CategoryGroupHeader that rotates on expand
5. Show all N habits inline when expanded (keep the "Show all" link as a secondary action if we want a partial reveal, or just show all)

Minimal diff. ~20-30 lines total across CategoryGroupSection + CategoryGroupHeader.

Open example styling

When a category is expanded, the row gets a subtle background color shift (warm off-white) so open state is visually distinct. Chevron rotates 180°. Habit rows render inside the card with a divider line between header and body.

Only one category can be tracked in state at a time OR multiple can stay open — I recommend multiple can stay open so user can compare across categories. Same as before with per-category expand.
