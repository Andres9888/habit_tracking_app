Why this matters

The shared <Card> primitive is the floor for "container shape" in the design system. With 12px it silently disagrees with every other card primitive. The fix prevents future drift — any new screen that reaches for <Card> now inherits the right shape.

05
EmptyState refactor — Blocked on design call

⏸ Forge C stopped before writing code. Two findings:

1. Migration target was deleted. HabitsEmptyState.tsx (the 1,094-line offender) was removed in PR #1216 (April 2026) with the rationale "when a user deletes their last habit, the app stays on the same page with the calendar header and bottom bar visible instead of navigating to a separate empty state screen." Re-creating it as a thin wrapper would be a UX regression. Project CLAUDE.md's "Critical Files Requiring Decomposition" list is stale.

2. The existing EmptyState.tsx already has a different variant axis. It's 135 lines (not the trivial scaffold the plan implied) with variant: noHabits | noData | noResults | premiumLocked used by 4 callsites (HabitsApp, TemplatesEmptyState, TemplatesListEmpty, AnalyticsScreen/EmptyState). The plan's variant: hero | section | inline is a different conceptual axis (visual scale vs. semantic state).

Needs your call:

  • Drop step 2 (the deleted migration target) entirely, OR pick a substitute callsite (TemplatesEmptyState? AnalyticsScreen/EmptyState?) as the new exemplar.
  • For the refactor itself, pick a reconciliation: (A) additive — add scale prop alongside existing variant, lowest risk; (B) rename existing variant → kind, break 4 callsites cleanly; (C) deprecate via soft prop.
  • Also flag: do you want me to also fix the stale CLAUDE.md "Critical Files" list while we're in here?
