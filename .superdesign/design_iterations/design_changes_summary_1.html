○ None Reanimated springs — use presets + overrides · 4 sites
HabitCard/entrance/animations/widthExpansion.ts · StrengthRing/useStrengthRingAnimation.ts · DraggableHabit/useCardStrengthFill.ts · DraggableHabit/useStrengthAnimation.ts
Where they live: four different motion moments.
  • Width-expansion of the left accent bar when a habit card enters (HabitCard).
  • Strength-ring value animation on the Habit Detail hero (StrengthRing).
  • Watercolor fill-background width on Today's habit cards (DraggableHabit).
  • Progress-bar width increase animation on strength bump (DraggableHabit).
Each now reads as { ...springs.gentle, damping: N, mass: M, stiffness: S } — the specific damping/stiffness/mass values are preserved as explicit overrides, so the motion feel is identical. Only the code reads as derived-from-preset instead of magic numbers.
−withSpring(value, { damping: 12, mass: 0.8, stiffness: 80 })
+withSpring(value, { ...springs.gentle, damping: 12, mass: 0.8, stiffness: 80 })
◐ Minor HabitCard accent-bar spring — shifted to bouncy preset
src/components/HabitCard/entrance/animations/widthExpansion.ts:49
Where it lives: the thin colored vertical bar on the left edge of every habit card — when a card first appears it slides in (sheet spring) and then the bar's width expands with a slight bounce. This is the width bounce.
What shifted: damping went from 12 → 10 (the springs.bouncy preset value), stiffness 180 and mass 0.8 preserved. Feels slightly bouncier. Watch when a new habit card mounts.
−withSpring(ACCENT_TARGET_WIDTH, { damping: 12, mass: 0.8, stiffness: 180 }, ...)
+withSpring(ACCENT_TARGET_WIDTH, { ...springs.bouncy, mass: 0.8 }, ...)
○ None Dependency removed — @expo/vector-icons
package.json · package-lock.json
Zero imports in src/ — the app already uses lucide-react-native everywhere (291 files). The explicit "@expo/vector-icons": "^15.0.2" declaration is gone. The package remains in node_modules as a transitive dependency of expo itself, so no bundle-size win — just a cleaner declared-dependency list.

Everything below was out of safe mechanical scope this session. Each needs either per-file judgment or a design conversation.

Values 15, 16, 18, 32, 36 don't map cleanly to the typography scale (34/22/20/17/14/13/12/10). Either snap-to-nearest (visible change) or extend the scale with new tokens — a design-system decision.

Same mapping problem at the NativeWind layer.
Wave 2.4 remainder · 53 non-canonical borderRadius
Values 2, 5, 10, 14, 18, 20, 32. Snap-to-nearest would produce visible changes; each site wants a per-case decision.
Wave 2.5 · 757 raw hex values
Long tail — mostly one-off gradients, achievement colors, material tier constants. Case by case.
Wave 3.1 · Unified Button primitive
Proposed API in the canonical showcase — 3 sizes × 4 variants. Needs your API sign-off before I build it.
Wave 3.2 · EmptyState consolidation
17 distinct EmptyState.tsx files. Probably 10 can consolidate into the canonical src/components/EmptyState/EmptyState.tsx; 7 are chart-specific and stay custom. Each migration is a judgment call.
Wave 3.3 · Animated.Value → Reanimated · 31 files
Motion QA per component. Overlaps with the 14 remaining legacy Animated.spring friction/tension sites.
Wave 3.4 · NativeWind vs StyleSheet — architectural
300+ files mix both. Pick one, establish boundary rules, or migrate to a different system (tamagui / unistyles). Not a mechanical change.
