Issue Details & Fixes

● Background Color Drift

Templates screen uses #FFFFFF as base background while the app uses #F5F1ED (warm parchment). This creates a noticeable "cold" feel when entering the templates modal.

Fix: backgroundColor: colors.background in layoutStyles.ts and pass via useThemeColors()

● Card Surface Mismatch

#fff used in TemplateCard, MiniTemplateCard, and SectionHeader. App standard is colors.card (#EDEAE5).

Files affected: TemplateCard.styles.ts, cardStyles.ts, SectionHeader.tsx

● Dark Mode Breaking

All search, control, and category components hardcode light colors. In dark mode, text would be invisible and backgrounds would flash white.

25+ hex values need migration to theme tokens for dark mode support.

● Cool Gray vs Warm Stone

Templates uses Tailwind cool grays: #374151, #6B7280, #9CA3AF
App uses warm stone: #3D3833, #6B6560, #C4BFB7

Subtle but creates visual temperature inconsistency.

● H1 Typography Scale

Header: 28px / 800 weight
App H1: 22px / 700 weight

The oversized header creates visual weight that doesn't match the habits screen's compact, balanced feel. The 800 weight doesn't exist in the type scale.

● Horizontal Padding

Templates: 20px everywhere
App standard: 16px (spacing.base)

Affects: header, search, tabbar, categories, filter controls, mini cards — 6 style files.

● Active State Color

Control buttons use #111827 (near black) for active state. App uses primary[600] #059669 (forest green) for active/selected states.

This misses the opportunity to reinforce brand color as the active indicator.

● Category Color System

14 categories each have 4 hardcoded light-mode hex values (bg, bgSelected, border, text). Consider using primary[600] as the universal expanded state color, with category emoji providing sufficient differentiation.
