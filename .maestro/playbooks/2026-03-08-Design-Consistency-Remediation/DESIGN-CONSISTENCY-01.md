# Phase 01: P0 Quick Wins — Duplicate Animation Consolidation & Missing Tokens

**Goal:** Eliminate duplicate animation code, add missing duration tokens, replace local animation constants that have exact theme equivalents.

**Context:** The design audit found 3 pairs of near-identical animation files, 4 local constants that duplicate theme tokens, and 3 commonly-used duration values (50ms, 80ms, 120ms) with no corresponding token.

---

- [ ] **Add missing duration tokens to `src/theme/animations.ts`**: Add `micro: 50` (for instant press feedback in emoji cells), `wobble: 80` (for shake/wobble micro-animations used in strength indicators), and `exit: 120` (for quick exit fades in card/content removal). These values appear 10+ times across the codebase with no token to reference. Keep the existing token order (alphabetical by name). Also add a `press` alias equal to `instant` (100ms) for semantic clarity in button press contexts. Update the JSDoc comment block to document the new tokens.

- [ ] **Consolidate duplicate level-up + pulse animations into shared module**: `src/components/DraggableHabit/animationHelpers.ts` and `src/components/HabitStrengthIndicator/animations.ts` contain near-identical code (`runLevelUpAnimation`/`animateLevelUp` and `runSubtlePulse`/`animatePulse`). Also `src/components/StrengthProgressBar/strengthAnimationHelpers.ts` duplicates the same wobble pattern (lines 64-66). Create `src/utils/animations/strengthAnimations.ts` with the canonical implementations (`runLevelUpAnimation` and `runSubtlePulse`), importing from `@/theme/animations` for spring tokens. Then update `DraggableHabit/animationHelpers.ts` to re-export from the new shared module (keep the file as a barrel for backwards compat). Update `HabitStrengthIndicator/animations.ts` to re-export from the shared module. Update `StrengthProgressBar/strengthAnimationHelpers.ts` to import the wobble pattern from the shared module instead of inlining it. Verify all three components still work by checking their imports resolve correctly.

- [ ] **Replace `MilestoneProgress/animation.constants.ts` with theme token imports**: The file `src/components/ProgressSectionConsolidated/MilestoneProgress/animation.constants.ts` defines 4 constants that have exact theme equivalents: `ENTRANCE_DURATION: 300` = `durations.moderate`, `PROGRESS_BAR_DURATION: 800` = `durations.progress`, `PULSE_DURATION: 2000` = `durations.drift`, `CELEBRATION_DURATION: 3000` = `durations.celebration`. Rewrite the file to import and re-export from `@/theme/animations` instead of defining its own values. Then update `src/components/ProgressSectionConsolidated/MilestoneProgress/useAnimationEffects.ts` (and any other files importing from this constants file) to use the theme token names directly if possible, or keep the re-exports for backwards compatibility.

- [ ] **Consolidate duplicate toast animation logic**: `src/components/ArchiveUndoToast/useArchiveUndoToast.ts` and `src/components/DeleteUndoToast/useDeleteToastAnimations.ts` contain near-identical show/hide/auto-dismiss animation logic. Extract the shared animation pattern (opacity fade in/out with spring-based translateY) into `src/utils/animations/toastAnimations.ts`. The shared module should accept configuration (auto-dismiss duration, spring config) and return animated values + trigger functions. Update both toast hooks to use the shared module. Both files already import `springs` from `@/theme/animations` — the shared module should do the same.

- [ ] **Add press/hover scale constants to `src/theme/animations.ts`**: The audit found inconsistent scale values for press states across components: card press (0.97), chip press (0.95), CTA press (0.98), chip hover (1.05), pop animation (0.8 -> 1.1 -> 1.0). Add a `scales` export object to `src/theme/animations.ts` with: `pressSubtle: 0.98` (for CTAs, large buttons), `pressStandard: 0.95` (for chips, small interactive elements), `pressCard: 0.97` (for card-level press), `hoverLift: 1.05` (for hover states), `popOvershoot: 1.1` (for pop/celebration effects), `popShrink: 0.8` (for pop start state). Export from `src/theme/index.ts` alongside other animation exports. Do NOT update component usages yet — that's a separate phase.

- [ ] **Add opacity constants to `src/theme/animations.ts`**: The audit found press opacity varies between 0.5, 0.7, 0.75, 0.85 across components. Add an `opacityValues` export object: `pressStandard: 0.7` (most common press opacity), `disabled: 0.5` (disabled state), `disabledText: 0.3` (disabled text specifically), `hover: 0.85` (hover/focus state), `backdrop: 0.6` (modal backdrop — already used in theme index.ts). Export from `src/theme/index.ts`. Do NOT update component usages yet.
