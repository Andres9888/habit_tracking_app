## Security Notes

### Authentication (SEC-001)

All mutations and most queries require authentication via Clerk:
```typescript
const identity = await ctx.auth.getUserIdentity();
if (!identity) throw new Error('Unauthenticated');
```

### Ownership Verification (SEC-001)

All user data mutations verify ownership:
```typescript
if (habit.userId !== identity.subject) {
  throw new Error('Not authorized');
}
```

### Input Validation (SEC-003)

All inputs are validated:
- **Short text**: Max length, XSS protection
- **Long text**: Max length, dangerous pattern detection
- **URLs**: HTTPS required, allowed domains only
- **Emojis**: Valid emoji validation
- **Dates**: YYYY-MM-DD format validation

### Premium Gating (SEC-005)

Premium features check via:
```typescript
const isPremium = await hasPremiumAccess(ctx, identity.subject);
if (!isPremium) throw new Error('Premium required');
```

### Internal Mutations

Internal mutations (prefixed with `internal.`) are:
- Only callable from server-side code
- Used for scheduled tasks, webhooks
- Not exposed to client

## Performance Notes

### Index Usage

- All queries use indexed fields (e.g., `by_userId`, `by_habit_and_date`)
- Avoid full table scans where possible

### Batch Operations

- Use batch queries instead of N+1 patterns
- `getStreaksForHabitsBatch()` for bulk streak calculations

### Caching

- Scheduled mutations with delays for batching rapid toggles
- Strength recalculation runs 500ms after toggle
