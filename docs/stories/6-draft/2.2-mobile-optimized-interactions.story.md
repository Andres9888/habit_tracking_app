# Story 2.2: Mobile-Optimized Interactions & One-Handed Use

**Status:** Draft
**Epic:** 2 - Mobile-First Engagement & Motivation
**Story ID:** 2.2
**Created:** 2025-10-12

---

## User Story

**As a** mobile user,
**I want** quick gesture-based interactions and thumb-friendly controls optimized for one-handed use,
**so that** I can efficiently manage my habits while walking, commuting, or multitasking.

---

## Acceptance Criteria

### AC1: Swipe Actions for Habit Management

- [ ] Swipe right on any habit card to mark complete (instant completion, no tap needed)
- [ ] Swipe left on any habit card to open quick actions menu (edit, archive, notes)
- [ ] Swipe actions show visual preview during gesture (color change, icon reveal)
- [ ] Swipe completion includes haptic feedback and subtle animation
- [ ] Swipe threshold: 80px for completion, 120px for menu reveal

### AC2: Quick Action Floating Button

- [ ] Floating action button (FAB) positioned in bottom-right corner, thumb-friendly zone
- [ ] FAB expands on tap to show: Add habit, View calendar, Statistics, Settings
- [ ] FAB collapses automatically after action or timeout (3 seconds)
- [ ] FAB includes subtle animation on scroll (fade out/down, reappear on scroll up)
- [ ] FAB respects safe area insets on modern devices with notches

### AC3: One-Handed Layout Optimization

- [ ] Primary action zones positioned within 40-70mm from bottom edge (thumb reach)
- [ ] Habits list optimized for vertical scrolling with minimal horizontal movement
- [ ] Date selector moved to bottom for easier thumb access when holding device
- [ ] Settings and secondary actions moved to slide-out drawer or FAB menu
- [ ] Text sizes and touch targets optimized for readability and accuracy

### AC4: Gesture Navigation

- [ ] Pull-to-refresh habit list with visual feedback and loading states
- [ ] Swipe between different date ranges (today, week, month views)
- [ ] Long-press on habit cards for drag-and-drop reordering
- [ ] Double-tap on habit to quickly add notes or view details
- [ ] Pinch-to-zoom on calendar views for better date selection

### AC5: Smart Quick Complete

- [ ] Large tap targets (44px minimum) for habit completion circles
- [ ] Edge swipe from right side of screen to complete top habit without looking
- [ ] Voice control integration: "Hey Siri, complete [habit name]" (iOS) / "Ok Google, complete [habit name]" (Android)
- [ ] Shake-to-complete feature for quick completion when device is in pocket
- [ ] Smart suggestions based on time and location

### AC6: Adaptive Interface

- [ ] Interface adapts based on device orientation (portrait/landscape)
- [ ] Left-handed mode option mirrors FAB and swipe actions
- [ ] Dynamic layout adjustment based on device size (phone vs tablet)
- [ ] Contextual actions appear based on usage patterns
- [ ] Smart positioning of elements based on grip detection

## Dev Notes

### Technical Context

**Current Implementation (src/App.tsx):**

- Basic tap-to-complete functionality exists
- Simple vertical scrolling list
- No current gesture handling beyond basic React Native gestures
- Settings accessible via header button

**Required Technologies:**

- `react-native-gesture-handler` (already installed)
- `react-native-reanimated` for smooth animations
- `react-native-haptics` for feedback
- Device API integration for voice commands
- Accelerometer for shake detection

### Touch Zone Analysis

**Optimal Thumb Reach (iPhone 12/13/14 dimensions):**
- Primary zone: 40-70mm from bottom edge
- Comfortable zone: 30-90mm from bottom edge
- Stretch zone: 20-120mm from bottom edge

**Target Touch Sizes:**
- Primary actions: 44-48px (Apple HIG recommendation)
- Secondary actions: 32-36px
- Edge swipes: 16-20px activation area

### Component Structure

**New Components Needed:**

1. **`SwipeableHabitCard.tsx`** - Enhanced habit card with swipe actions
2. **`FloatingActionButton.tsx`** - Expandable FAB with menu
3. **`GestureNavigation.tsx`** - Navigation gesture handling
4. **`QuickCompleteZone.tsx`** - Edge swipe quick complete area
5. **`AdaptiveLayout.tsx`** - Layout adaptation logic

**Updated Components:**

1. **`App.tsx`** - Integrate gesture system and FAB
2. **`DraggableHabit.tsx`** - Add swipe actions and quick complete
3. **`DateSelector.tsx`** - Move to bottom position, add swipe navigation

### Gesture Specifications

**Swipe Actions:**
- Complete swipe: Right, 80px threshold, 300ms timeout
- Menu swipe: Left, 120px threshold, 400ms snap-back
- Visual feedback: Color gradient + icon reveal
- Haptic: Light for complete, medium for menu

**FAB Behavior:**
- Idle state: 56px circular button, 24px icon
- Expanded state: 280px arc menu, 4 action items
- Animation: 250ms spring transition
- Auto-collapse: 3000ms timeout

**Pull-to-Refresh:**
- Activation threshold: 80px pull distance
- Visual feedback: Spinner + loading animation
- Refresh indicator: 40px height max
- Spring physics: 0.8 damping, 300ms duration

### Voice Integration

**iOS Siri Shortcuts:**
- "Complete [habit name]" → API call to toggle habit
- "Show my progress" → Open detailed view
- "Add new habit [name]" → Open add dialog
- Context-aware suggestions based on time/location

**Google Assistant Actions:**
- Similar command structure to iOS
- Deep linking to specific app screens
- Voice feedback confirmations

### Performance Considerations

- Gesture recognition should not block main thread
- Use `runOnJS` for gesture callbacks that trigger state updates
- Limit gesture event frequency with throttling (16ms for 60fps)
- Optimize re-rendering during swipe gestures
- Memory management for gesture recognizers
