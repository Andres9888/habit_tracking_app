Why this happens

The section computes two different truths and hands them to two different consumers. remindersActuallyDeliveryOn = enabled && permissionGranted drives the switch and the card's pointerEvents, but the expand animation is fed the raw props.enabled:

// StreakRemindersSection.tsx:28 — the animation never learns about permission
- const animations = useStreakRemindersAnimations(props.enabled);
+ const animations = useStreakRemindersAnimations(remindersActuallyDeliveryOn);

So with reminders enabled in-app but denied by iOS, the height animation expands (enabled === true) while the switch renders off and pointerEvents='none' kills every touch inside. The result is a card that looks live, looks scheduled, and silently absorbs taps.

Why it matters: this is the one screen state where the app is not doing what the user asked. It has to read as unambiguous — a visible “8:00 PM” next to a switch that says nothing is sending teaches users the setting is broken rather than blocked. One-line change; remindersActuallyDeliveryOn is already in scope on the line above.

Bonus: once the card is gone, the “Blocked in settings. Not sending reminders.” subtitle on the switch is redundant with the warning row directly above it — the row can go back to its normal “Nudge before an active streak slips” copy, as shown.

Why this happens

Two halves of the same feature disagree about the platform. The picker renders unconditionally on iOS:

// ReminderInsetCard.tsx:52
{Platform.OS === 'ios' ? ( <DateTimePicker display='spinner' … /> ) : null}

// StreakRemindersSection.tsx:35 — the toggle handler ignores iOS entirely
const handleToggleTimePicker = () => {
  if (Platform.OS === 'android') setShowTimePicker(true);
};

Because the spinner is always visible on iOS, nothing needed to open it — so the handler was written for Android only. But ReminderTimeRow still wraps the pill in an AnimatedPressable that fires triggerHaptic('selection') before calling that no-op. The user gets tactile confirmation that something happened, and then nothing does. That's worse than a plainly non-interactive label.

The fix is one prop plus one branch: switch to display='compact' and let the native control own its own popover — then the custom pill and its dead handler can be deleted outright, since the compact picker renders as that same tinted pill. Alternatively keep the pill and make the handler set showTimePicker on both platforms.

Why it matters: reminder time is a set-once decision. Spending the most valuable third of the sheet on it permanently — and burying “Your habits & data” below the fold — inverts the frequency ranking of the whole screen.

Why this happens

The row component gives info rows half the lines it gives everything else:

// RowLabel.tsx:29
numberOfLines={type === 'toggle' || type === 'navigation' ? 2 : 1}

The permission warning is a type='info' row carrying both a value pill ('Open settings') and the longest label in the module — 'Reminder delivery blocked'. One line minus the pill's width leaves room for about thirteen characters, hence “Reminder deli…”. The subtitle gets two lines but the same squeezed column, so it dies at “to res…”.

The profile line is a plain authoring bug: ProfileHeroIdentity.tsx:69 renders {planLine}. Plan, billing, email & sign out where planLine is already 'Plan: Free' — so the word appears twice before the ellipsis eats the rest.

Why it matters: truncation is never uniformly bad — it's bad in proportion to how much the reader needed that string. Here it lands on the one row explaining why a feature is dead, and on the row that tells someone which plan they're paying for. Prefer shortening the copy over raising numberOfLines: two-line labels beside a pill would fix the clipping but make every info row taller and ragged. “Notifications are off” is both shorter and clearer than “Reminder delivery blocked”.
