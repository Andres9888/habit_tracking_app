// Analytics events tracked: onboarding_started → User begins onboarding flow onboarding_screen_viewed → User sees a specific screen (with index, name) onboarding_screen_completed → User completes a screen (with time_spent_ms) onboarding_skipped → User skips onboarding (with screen, reason, total_time) onboarding_completed → User finishes all screens (with total_time_ms) onboarding_recovered → User returns to in-progress onboarding (with recovery_screen) // Example usage (extend with your analytics provider): import { setOnboardingAnalyticsTracker } from '@/screens/onboarding'; setOnboardingAnalyticsTracker({ track: (event, properties) => { posthog.capture(event, properties); // Or Mixpanel, Amplitude, etc. } });
🔄 Onboarding Recovery

Users who exit during onboarding (app closed, crash, distraction) can now resume where they left off

❌ Before
User closes app on screen 2:
  • Reopens app → starts from screen 1 again
  • Gets frustrated, skips entirely
  • Lands on empty state with no context
  • Result: Confused user, low completion rate
✅ After
User closes app on screen 2:
  • Progress automatically saved to AsyncStorage
  • Reopens app → sees friendly banner: "👋 Welcome back! Continue where you left off"
  • Resumes on screen 2, seamlessly continues
  • Result: Delightful UX, higher completion rate
