entitlements. Interactive device/browser click-through is not available in a headless CI container
(no simulator, no provisioned Convex deployment). The **highest-fidelity real-user layer that runs

- mounts **real screens through the real provider stack**

  from the **real** `convex/analytics*` compute functions);

  the Convex transport, native device modules, and the paywall SDK — matching production conditions.

## 3. User-facing surface inventory

Source map (entry points): `src/App.tsx` → `src/components/auth/AuthGate.tsx` →
`src/features/habits/HabitsApp.tsx`. Navigation is state/overlay driven (no file-based router).

### 3.1 App-level states (`AuthGate`)

Signed-out (`WelcomeScreen`) · Loading (`BrandedLoadingScreen`) · Onboarding
(`OnboardingFlowV2`, flag-gated) · Paywall (`RevenueCatPaywall`, flag-gated) · Authenticated
(`HabitsApp`). In-app: skeleton loading, empty state, error boundaries, **offline mode**
(`NetworkStatusContext` + optimistic queue), selection/batch mode, premium vs. free gating.

### 3.2 Roles / entitlements

No admin/user role system — every authenticated user owns only their own data (ownership enforced
server-side by `userId === identity.subject` and IDOR checks in `convex/users.ts`, `habits.ts`,
etc.). The only tier distinction is **premium vs. free**, sourced from RevenueCat
(`usePremium()`) and validated server-side (`convex/subscriptions.ts`,
`grantPremium`/`revokePremium`/`setBillingIssue` via webhook, with idempotency on
`lastWebhookEventId`).

### 3.3 Screens

`WelcomeScreen`, `OnboardingFlowV2` (14 steps), `HabitsApp` (home + week strip + bottom action bar),
`HabitDetailScreen` (Calendar / Strength / Goal tabs), `HabitEditScreen`, `AnalyticsScreen`
(premium), `CharacterScreen` (gamification), `TemplatesScreen`, `RevenueCatPaywall`.

### 3.4 Modals / sheets / overlays

Settings, Create Habit, Habit Edit, Habit Calendar, Pause Habit, Archived Habits, Paused Habits,
Share Card, Quick Actions sheet, Make-It-Stick sheet, Activation modal, Visualization Exercise,
Templates, EmojiPicker sheet, Pack Confirm sheet, Day Habits sheet, Batch-Delete confirm.
Toasts/banners: Archive-undo, Delete-undo, Completion, Template-added, Trial countdown,
Offline-pending, Draft recovery, Sync-status.

### 3.5 Convex backend surface

`habits` (CRUD, archive/unarchive/pause/resume/remove/restore, reorder, toggleHabit, batch ops),
`tracking` (completion status, strength update), `settings` (get/update), `subscriptions`
(premium lifecycle), `users` (getOrCreate, currentUser, GDPR delete), `analytics*` (overview,
distribution, trend, compliance, weekly), `templates` (list/import/usage), `categories`, `storage`
(upload URL + image validation), `habitStrength`, `streakUtils`. All queries/mutations gate on
`ctx.auth.getUserIdentity()`.

### Risk-based edge cases verified in pure-logic suites (and their canonical behavior)

- **Streak expiry:** a streak whose latest completion is > 1 day before today returns **0**

  `calculateStreakFromHistory`.
- **Habit-name validation:** empty → rejected ("cannot be empty"); > 100 chars → rejected +
  sanitized to 100; dangerous patterns stripped. (`MAX_HABIT_NAME_LENGTH = 100`.)
- **Offline:** optimistic toggle, pending-sync badge, queue persistence, sync on reconnect
  (`src/lib/offline/*`).
- **Subscriptions:** webhook idempotency; cancellation keeps access until period end; only
  expiration revokes; billing issue → grace period.

### Edge cases NOT exercisable headlessly (recommended for device QA — Maestro/Detox)

Real push-notification delivery & tap routing; RevenueCat purchase/restore flow; image upload &
camera; haptics; store-review prompt; deep links. The `.maestro/` and `.detoxrc.js` configs exist
for this device layer.

## 7. Findings log (reproduction evidence + disposition)

Each finding includes a one-line repro. **F-1…F-3 are fixed this run** (code verified correct, test/doc
was stale). The rest are documented with disposition; numeric/taxonomy drift is **not** blindly
"fixed" because rewriting expectations to match current output would mask real regressions.

### F-1 — FIXED — Streak test asserted expired streak as 3 (canonical behavior is 0)

- **Repro:** `npx jest src/lib/offline/calculations/streakCalculator.test.ts -t "not within today"`
- **Evidence:** test "returns 0 when most recent is not within today" asserted `.toBe(3)`. The
  canonical `src/utils/streak.ts` documents that a > 1-day gap returns **0** (streak expired); the
  offline `computeCurrentStreakFromDates` matches it (and so does server-side
  `calculateStreakFromHistory`). The test name and a stale comment contradicted the assertion.
- **Disposition:** Product code correct. Corrected the assertion to `.toBe(0)` and fixed the comment.
  The corrected test is the regression guard. ✅ suite now 56/56.

### F-2 — FIXED — Validation test expected the old 200-char limit

- **Repro:** `npx jest src/utils/__tests__/validation.test.ts -t "very long names"`
- **Evidence:** asserted `error` contains "200 characters or less" and `sanitized` length 200, but
  `MAX_HABIT_NAME_LENGTH = 100` (`src/constants/app.ts`) and the runtime message/sanitization use 100.
- **Disposition:** Product code correct. Updated assertions to 100. ✅ suite now passes.

### F-3 — FIXED — Stale `@example` in `validateHabitName` docstring

- **Evidence:** `src/utils/validation.ts` JSDoc example claimed the error says "200 characters or
  less"; the implementation emits the value of `MAX_HABIT_NAME_LENGTH` (100).
- **Disposition:** Corrected the docstring example to 100 (production doc accuracy).

### F-4 — DOCUMENTED — `getSmartReminderDefault` taxonomy drift

- **Repro:** `npx jest src/utils/__tests__/reminderDefaults.test.ts -t "Boundary transitions"`
- **Evidence:** test expects a "midday" bucket with 7AM/12PM/8PM boundaries; the current function
  uses a different category model (no "midday"; "Coverage across all 24 hours" expects 11 vs 24).
- **Disposition:** Likely stale test after an intentional taxonomy change. Needs a product decision on
  the intended buckets before the test is rewritten — **do not** auto-fix. See REM-3.

### F-5 — DOCUMENTED — `habitStrength` expected values drift (~0.4%)

- **Repro:** `npx jest convex/habitStrength.test.ts -t "decay on missed days"`
- **Evidence:** expected `2.8929` vs received `2.8812` (and similar). A parallel suite
  (`tests/unit/convex/habitStrength.test.ts`) **passes**, indicating the algorithm is in a
  deliberate state and `convex/habitStrength.test.ts` holds stale magic numbers.
- **Disposition:** Confirm the intended algorithm constants, then recompute fixtures. **Do not** paste
  current output over expectations (would mask regressions). See REM-3.

### F-6 — DOCUMENTED — Min-length habit-name expectation is ambiguous

- **Repro:** `npx jest src/utils/validation/__tests__/validation.test.ts -t "too short"`
- **Evidence:** test expects `validateHabitName('a').isValid === false`; `textValidation.ts` only
  rejects empty/over-limit. Two separate `validateHabitName` implementations exist
  (`src/utils/validation.ts` and `src/utils/validation/textValidation.ts`) — a duplication smell.
- **Disposition:** Product decision: are 1-char names allowed? If yes, fix the test; if no, add a min
  check to **both** validators. See REM-2/REM-4.

### F-7 — DOCUMENTED — Tests for removed `StatsNotesModal` feature (ENOENT)

- **Repro:** `npx jest tests/unit/theme/statsnotesmodal-tokens.test.ts`
- **Evidence:** reads `src/components/StatsNotesModal/HabitStats/WeeklyBarChart.tsx`, which **no longer
  exists** (feature removed). ~20 theme-token guardrail suites read source files from disk and break
  when files move/rename.
- **Disposition:** Delete tests for removed features; make remaining token-scanners resilient to
  missing paths. See REM-1.

### F-8 — DOCUMENTED — `dateUtils`/`getLocalDateString` no longer throw on invalid input

- **Repro:** `npx jest src/utils/__tests__/dateUtils.enhanced.test.ts -t "throws on invalid date"`
- **Evidence:** tests expect a `TypeError` on `'invalid-date'`; the functions now handle it gracefully.
- **Disposition:** Graceful handling is arguably the better behavior — update tests to assert the
  graceful contract. See REM-2.

### F-9 — DOCUMENTED (harness) — Missing provider wrappers in unit tests

- **Repro:** `npx jest src/components/HabitCard/...` (any using `useStreakMilestoneIntegration`)
- **Evidence:** "useStreakMilestone must be used within a StreakMilestoneProvider". The app always
  provides it via `LazyProviders` (e2e proves this), so it is **test-only**.
- **Disposition:** Provide a shared RNTL render wrapper (mirroring the e2e harness) for unit tests.
  See REM-1.

### F-10 — DOCUMENTED (harness) — Incomplete shared/inline animation & util mocks

- **Evidence:** `useAnimatedProps`/`withTiming`/`Easing.*` "is not a function", `clsx` not a function,
  `triggerSuccess` not a function (real `useHapticFeedback` export), lucide icon → undefined.
- **Disposition:** Complete `__mocks__/react-native-reanimated-mock.js` and add shared mocks for
  `clsx`/haptics/icons; migrate per-file inline mocks to the shared ones. See REM-1.
