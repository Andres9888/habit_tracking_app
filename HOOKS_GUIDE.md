## Usage Patterns

### Pattern 1: Composite Hook

Complex features use a main hook that composes smaller hooks:

```tsx
// Main entry point
export function useFeature(options) {
  const hooks = useFeatureHooks(options);
  const sideEffect = useFeatureSideEffect(hooks);
  
  return buildFeatureReturnValue(hooks);
}

// Internal composition
function useFeatureHooks(options) {
  const state = useFeatureState();
  const operations = useFeatureOperations(state, options);
  const handlers = useFeatureHandlers(state, operations);
  
  return { state, operations, handlers };
}
```

**Examples**: useAudioPlayback, useAudioRecording, useRescueTrigger

### Pattern 2: Data Hook with Memoization

Hooks that compute expensive derived data use useMemo:

```tsx
export function useExpensiveData(inputs) {
  return useMemo(() => {
    return computeExpensiveValue(inputs);
  }, [inputs]); // Only recompute when inputs change
}
```

**Examples**: useHabitStrength, useMilestoneDetection

### Pattern 3: Side-Effect Hook

Hooks that manage external side effects use useEffect:

```tsx
export function useSideEffect(config) {
  useEffect(() => {
    const subscription = setupListener(config);
    return () => subscription.remove();
  }, [config]);
}
```

**Examples**: useStreakReminders, useAppStatePlayback, useKeyboardVisible

### Pattern 4: Permission Hook

Hooks that require user permissions follow a request → check → use flow:

```tsx
export function useProtectedFeature() {
  const [hasPermission, setHasPermission] = useState(null);
  
  const requestPermission = async () => {
    const { status } = await requestAsync();
    setHasPermission(status === 'granted');
    return status === 'granted';
  };
  
  return { hasPermission, requestPermission, use: ... };
}
```

**Examples**: useAudioRecording (mic), useImagePicker (camera/photos)

## Best Practices

### 1. Hook Naming

- **DO**: `usePastTense` (useHabitStrength, useCompletedDates)
- **DON'T**: `useNoun` (useHabit ❌, better: useHabitData ✅)

### 2. Hook Composition

- Extract complex logic into smaller hooks
- Use builder functions for return values (see buildPlaybackReturnValue)
- Keep hooks focused on one responsibility

### 3. Performance

- Use `useMemo` for expensive computations
- Use `useCallback` for functions passed as props
- Use `useRef` for values that don't trigger re-renders
- Monitor with useRenderCount during development

### 4. Error Handling

- Provide `onError` callbacks in options
- Fail gracefully (non-critical features shouldn't crash app)
- Log errors in development, silently fail in production

### 5. TypeScript

- Define clear interfaces for options and return types
- Export types for consumer convenience
- Use discriminated unions for state (e.g., PlaybackState)

## Contributing

### Adding a New Hook

1. **Create the hook file** in appropriate category folder
2. **Add comprehensive JSDoc** with:
   - @description
   - @param for all parameters
   - @returns with detailed return type docs
   - @example with realistic usage
3. **Flag if >100 lines** with comment: `⚠️ Hook >100 lines - Consider refactoring`
4. **Update this guide** with new hook entry
5. **Add tests** if hook has complex logic
6. **Export from index.ts** in category folder

### JSDoc Template

```tsx
/**

 *
 * @description
 * [Detailed explanation]

 *     option1: true

 * ```
 */

  // Implementation
}
